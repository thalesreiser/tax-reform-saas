# @trs/api

Fastify 5 API: the internal routes used by the web app and the public `/v1` API (BE-03).

| Path            | What it is                                                        |
| --------------- | ----------------------------------------------------------------- |
| `/health`       | Liveness probe with the deployed version                          |
| `/openapi.json` | OpenAPI 3.1 document generated from the Zod schemas of each route |

## Conventions

- **Schemas:** every route declares its params, body and responses with Zod
  (`fastify-type-provider-zod`); types and the OpenAPI document come from them.
- **Errors:** every error response is problem details (RFC 9457, `application/problem+json`) with
  the `requestId`. Validation errors list each field in `errors[]`. A 5xx answer never carries the
  cause; the cause goes to the log.
- **Request id:** always generated by the server (UUID), returned in `x-request-id`; a
  client-supplied id is ignored.
- **Logs:** JSON (pino). `authorization`, `cookie`, `x-api-key` and `set-cookie` are redacted. Never
  log or reflect request bodies: they carry fiscal data, and echoing them is an XSS sink.
- **Configuration:** environment variables validated at start-up (`src/config.ts`, `.env.example`).
  An invalid value stops the process with the variable name, never its value.
- **Tests:** `app.inject()` against `buildApp()`, no open port.
